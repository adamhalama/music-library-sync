# AGENTS.md — Working Effectively In This Repo

## Project Overview
- `update-downloads` is a Go CLI (`udl`) that orchestrates music sync workflows from source URLs into local libraries with deterministic, source-by-source execution.
- Core runtime stays in Go (config loading/validation, preflight planning, retries, logging, and UX), while v1 download engines remain external adapters (`scdl`, `spotdl`).
- Primary workflows are `init`, `validate`, `doctor`, and `sync`, with YAML config + state/archive files used to track known tracks, detect gaps, and control break/scan behavior.


## Commit & Pull Request Guidelines
- Use short, imperative prefixes for both commit messages and PR titles: `feat:`, `fix:`, `test:`,`menu:`, `settings:`, `docs:`, `chore:`, `refactor:`.
- Keep commit/PR titles concise, present tense, and without a trailing period. Example: `test: cover scdl binary selection fallback`.
- PRs should include a brief summary, linked issue/ticket (if any), terminal output snippet or short clip for CLI UX/output changes, and the exact validation commands run (for example: `go test ./...`, `go vet ./...`, `go test -race ./...`, plus any manual `udl ...` checks).


## Security & Configuration Tips
- Keep GitHub App secrets/private key out of the repo; tokens live in Keychain. 

If you encounter a violation in the repo or in a proposed change, explicitly call it out and propose a safer alternative.
Do not quietly change security-sensitive behavior. Call it out.


## A Note To The Agent

We are building this together. When you learn something non-obvious, add it here so future changes go faster.
- As of Spotify Web API changes (Feb 2026), upstream `spotdl` `4.4.3` can fail on playlist metadata (`/playlists/{id}/tracks` 403) and missing artist fields (for example `genres`). A patched build from PR #2610 commit `27f3a0e33174170cbeebbcc0738ceb41a9baf947` works in local validation.
- If Spotify retries run with `--headless`, OAuth stays in manual copy/paste mode; removing `--headless` on the retry allows browser-led auth and is much clearer for interactive `udl sync` flows.
- `bambanah` `deemix-cli@0.1.0` can print a Spotify plugin stack trace (for example `TypeError: Cannot read properties of undefined (reading 'error')`) while still exiting `0`; `udl` must treat this as failure to avoid false-positive source success/state writes.
- For Spotify playlist sources run with `--no-preflight`, `udl` now enumerates tracks from the public playlist page and executes per-track (instead of passing the whole playlist URL once), so deemix cache priming still applies.
- Spotify state file format supports v2 metadata lines (`<id>\ttitle=...\tpath=...`) and remains backward-compatible with v1 ID-only lines; v2 metadata improves local-file detection when Spotify preflight metadata is sparse (for example HTML fallback).
- Shell-based subprocess tests can buffer stdout unexpectedly; for deterministic rate-limit guard tests, emit the trigger line on stderr so `SubprocessRunner` observers see it immediately.
- pyrekordbox `db6.tables.datetime_to_str` drops second precision when `datetime.microsecond == 0` (stores `YYYY-MM-DD HH:MM +00:00`); when writing `djmdContent.created_at` for deterministic Date Added ordering, always use non-zero microseconds (for example `.900000`) so seconds survive serialization.
- Public macOS releases now ship `udl` only; Homebrew installs `scdl` and `yt-dlp` as external dependencies, and tarball installs rely on `doctor` / TUI repair guidance when those tools are missing.
- Standalone playlist snapshots are cache-first and never refresh on open; Apple Music is read only after an explicit refresh, and failed or canceled refreshes must preserve the previous valid snapshot.
- Masked credential editors must keep the existing secret outside the editable buffer. Preloading a masked buffer causes a pasted replacement to append to the old secret (an ARL becomes two identical 192-character halves) while the UI makes the duplication invisible.
- Interactive plan rebuilds cross the engine/TUI channel boundary; when a selector changes a per-source option such as the Spotify plan window, update both the engine request and the TUI interaction's copied per-source state before rendering the rebuilt rows.
- Rekordbox process detection matches process names containing `rekordbox`; when building a temporary validation binary, name it `udl` or another neutral name so the safety guard does not mistake the validator for the Rekordbox application.
- `VerifyPlanChecksum` re-marshals the parsed `playlistsync.Plan`, so any new plan field must be `omitempty` (or the plan version bumped): an always-emitted field changes the JSON of plans written by older builds and makes them fail with an opaque "plan checksum mismatch" instead of a regenerate hint.
- Go nil slices in valid agent responses encode as JSON `null`; Swift collection DTOs for optional/empty protocol fields must use `decodeIfPresent(... ) ?? []` rather than requiring an array. `playlists.config.read` is the one that bites on a fresh install: with no `playlists.yaml` it returns `"playlists": null`, and a non-optional `[PlaylistDefinition]` turned that into a modal "playlist cache could not load" on first launch.
- `AgentProcess.stop()` must clear `process`/`client`/`connection` itself rather than waiting for `Process.terminationHandler`, which runs on its own queue and hops to the main actor. `restart()` calls `launch()` immediately, and `launch()` returns the existing client while `process` is still set — so a restart would hand back the client of the connection it had just closed and the next request would fail with "connection is closed". Onboarding's Finish Setup hit this every time. The termination handler must then guard on `self.process === process` so a late callback cannot tear down the generation that replaced it.
- `config.Validate` requires `state_file` for **both** source types the GUI can create (soundcloud and spotify). Any source editor that treats it as optional produces a config the backend refuses after the fact; the app's own `ConfigValidation` mirrors the rule so the refusal never has to happen.
- In the native app a disabled control states its reason next to itself, not only in `.help(_)`. A tooltip nobody hovers is the "silent disabling" failure mode the redesign exists to remove. `.constrained(by:)` is the sanctioned way to disable a control; `SourceRuleTests` budgets the remaining bare `.disabled(` sites per file and each budget carries its justification.
- A failure caused by an action on a screen is reported *on that screen*, through that workflow's `AppState.WorkflowStatus`. `alertMessage` — the blocking modal — is reserved for session-level failures no screen owns: backend launch, restart, an undecodable protocol frame, and a reply the app cannot deliver while the backend is blocked waiting for it. `SourceRuleTests` enforces the allowlist.
- `@DefaultEmpty` (in `Backend/Wire/WireModels.swift`) is how every wire-inbound collection tolerates Go's `null`. Its `init(wrappedValue:)` must stay the only initialiser callable with no arguments, and `wrappedValue` must not have a default — either one silently makes Swift synthesise memberwise initialisers taking `DefaultEmpty<Value>` instead of the bare collection, which breaks every construction site.
- A default that is written twice will drift. `SyncDefaults` is the single source for the sync run's defaults; the `@Published` initialisers and `resetSyncAdvanced()` both read it, after a comment claiming "dry run is the default" and an initialiser saying `false` disagreed for a whole phase.
- To drive the app for manual verification, `.dev/app.sh` places `UDL-Dev.app` on the built-in display and screenshots it, and `.dev/ui` posts clicks/keys. Synthetic keystrokes do not reach SwiftUI `TextField`s reliably; set the value through the accessibility tree (`System Events` → `set value of text field …`) and then send Tab, because the binding commits when focus leaves.
- Unexpected backend EOF can race the process termination handler. Native recovery UI must distinguish deliberate shutdown by cancellation of the connection observer, not by checking whether `AgentProcess.state` is still `.running`.
- Destructive-path Rekordbox acceptance is opt-in: set `UDL_REKORDBOX_ACCEPTANCE_PYTHON` to an absolute pyrekordbox-capable Python and run `TestRekordboxIsolatedApplyAndRestore`; it copies the checked-in sandbox DB to `t.TempDir`, applies there, and verifies exact-backup restoration byte-for-byte.
- First-run onboarding is suppressed when either an enabled standalone Free DL job or a valid Rekordbox configuration exists, even if the main config has no sync sources. Tests for the no-source route must isolate user-level standalone configs explicitly.
- The Free DL hardening smoke's browser-launch-failure leg requires a track whose SoundCloud purchase URL uses a supported gate such as Hypeddit; a generally free-to-use track may still classify as `unsupported-free-download-host` and never reach the browser launcher. Promotion logs use `library <= free source` direction.
- macOS app distribution intentionally uses only free ad-hoc signing (`codesign --sign -`), never Developer ID or notarization. Release docs must call the app unidentified, publish a checksum, and describe macOS's one-time Privacy & Security → Open Anyway flow without claiming Apple verification.
- On a Mac with Command Line Tools but no full Xcode, use `make app-dev` (or `make app-dev-open`): `packaging/dev/build_macos_app.sh` directly compiles the current-architecture Swift sources, embeds `bin/udl`, materializes the `UDL Dev` plist (`com.jaa.udl.dev`), and ad-hoc signs the bundle.
- Command Line Tools do not ship the Swift XCTest module. `make app-test-dev` compiles the real `UDL` production module with testing enabled, supplies a narrow XCTest-compatible module only to the test target, and executes the unchanged `macos/UDLTests/*Tests.swift` sources; keep that shim out of the Xcode project so full-Xcode builds continue using Apple XCTest.
- Agent protocol v2 separates `sync.progress` from lossless `sync.event`: Go must flush pending newest-only progress before lifecycle/terminal frames, while Swift must buffer only progress with `.bufferingNewest(1)` and keep lifecycle/`run.finished` lossless. Never put both traffic classes back onto one bounded stream.
- Spotify/deemix source runs own one advancing media-snapshot baseline and one cached `spotifyStateWriter`; failed/unavailable invocations still advance the snapshot, and each completed track must atomically persist through the cached writer before the next invocation. A writer for a new empty file must retain the v2 header in its cached prefix—generating the header only during the first persist drops it on the second track.
- Native sync cancellation has two independently ordered replies: `run.finished` can arrive before the outstanding `run.cancel` response. Once `exitCode` is terminal, a late cancellation acknowledgement or error must never replace the terminal message; terminal delivery also finalizes any retained planning/running source-table lifecycle because cancellation during `ui.selectRows` may produce no later per-source snapshot.
- `make app-dev-install` is the repeatable local macOS install loop: it builds and signs the app, replaces `~/Applications/UDL-Dev.app` through a verified staging copy, restores the previous install on failure or cancellation, registers it with Spotlight, and opens it.
- Cross-workflow playlist handoffs must preserve the standalone `playlist_id`: opening Rekordbox generically falls back to a job/config target and loses the cached snapshot. Provider-facing refresh copy must also come from the definition (`apple_music` vs `navidrome`), because a Navidrome snapshot refresh never contacts Music.app.
- Directional Rekordbox/Navidrome pairs keep provider IDs in checksummed state rather than YAML so exact-name selections survive external renames; job IDs must be case-insensitively unique because they name files on commonly case-insensitive macOS state volumes.
- OpenSubsonic playlist replacement should discover `formPost` and send repeated `songId` form values. Creation-by-name is not generically retryable: after a lost response, re-list exact-name playlists and accept only one whose exact ordered membership matches the plan; otherwise report partial/uncertain state and require a fresh plan.
- Cross-provider playlist matching uses one exact real-path identity (`internal/pathidentity`): decode one file-URL layer, clean, normalize Unicode to NFC, preserve case, and never fall back to artist/title metadata.
- Home's preview action sets the shared `syncDryRun` flag for that run. `resetSyncRun()` must restore `SyncDefaults.dryRun` so "Configure another run" cannot leak preview mode into the next ordinary Run Sync; the ordinary route defaults live and preview remains an explicit Advanced option.
- `engine.SupportsPlan` must list every adapter kind registered in `NewSyncer`'s `PlanRegistry`. Free DL capture (`freedl.capture.start`) runs as a sync with `Plan: true`, so an adapter missing from the predicate is skipped with a warning while the run still exits `0` — the capture reports success and downloads nothing. `TestSupportsPlanCoversEveryRegisteredPlanAdapter` asserts the predicate against the registry so they cannot drift.
- ffmpeg attributes options positionally: anything between two `-i` flags is parsed as an *input* option for the second input. Artwork embedding must declare both inputs before any `-map`/`-codec`, or every embed fails with "Option map ... cannot be applied to input url" and silently degrades to the no-artwork fallback.
- A SoundCloud `purchase_url` backs both the `FREE DL` and the `Buy` button with no machine-readable distinction, so free-DL support is a host allowlist (`freeDownloadGateHosts`). Gate services (`hypeddit.com`, `gaterush.me`, `droploud.com`, `mypresskit.info`) are in; stores and smart links (`bandcamp.com`, `found.ee`) are deliberately out, because opening them can never yield a file and each attempt costs a full browser-gate wait.
- The deemix Spotify plugin matches a Spotify track to Deezer **by ISRC**, and a primed `config/spotify/cache.json` entry is authoritative. An entry carrying only `data` (title/artist/album) with no `isrc` makes deemix fail *every* track with `GWAPIError: Track unavailable on Deezer` — a false negative that looks exactly like a genuinely unavailable catalogue. Writing no entry at all is worse: deemix's own Spotify lookup is broken post-Feb-2026 and silently returns one unrelated track for every input, so it downloads the wrong audio without erroring. `udl` therefore resolves the ISRC itself (`/v1/tracks/{id}` still answers for client-credentials tokens even though `/playlists/{id}/tracks` returns 403) and primes the cache with it.
- Spotify Web API access is uneven per endpoint: `/v1/playlists/{id}` (name/owner) and `/v1/tracks/{id}` work with a client-credentials token, while `/v1/playlists/{id}/tracks` and the bulk `/v1/tracks?ids=` return 403. Playlist enumeration therefore falls back to scraping `open.spotify.com`, which yields IDs but no ISRC — hence the per-track ISRC lookup during enrichment.
- `udl` discovers a repo-local `udl.yaml` before `~/.config/udl/config.yaml`; when validating real user sources from inside the checkout, pass `-c ~/.config/udl/config.yaml` explicitly or `validate`/`sync` will silently operate on the repo's sample config.
- `sync` requires `target_dir` to already exist and fails the source with `target_dir does not exist` rather than creating it; create the directory when adding a new source by hand.
- `udl` on `PATH` is the Homebrew release (`/opt/homebrew/bin/udl`), not this checkout. When a user reports TUI behaviour, check `udl --version` before debugging current code; 0.2.0 predates the Spotify `latest` plan window and plans playlist order, so break-on-existing stops at the oldest downloaded track.
- To drive the Bubble Tea TUI headlessly (no tmux), run it under a Python `pty` with `pyte` and answer its startup queries (`ESC]11;?` background colour and `ESC[6n` cursor position); it renders nothing until both are answered. The interactive sync workflow starts with every plan-capable source ticked.
- Free DL promotion's ffmpeg `-map_metadata` silently drops MP4 iTunes freeform `WWWAUDIOFILE` fields; ExifTool `-TagsFromFile -all:all` also did not retain them in the September 12 batch. `.dev/freedl-0912/preserve.py restore-tags` copies the complete MP4 tag set with Mutagen, verifies exact encoded audio/artwork hashes before replacement, and preserves macOS creation time. Use the audit's audio-stream bitrate, not container bitrate (which includes artwork).
