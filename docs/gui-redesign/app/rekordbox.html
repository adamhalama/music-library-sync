Rekordbox Sync

The risky workflow is intentionally plan-first. Every intended playlist mutation is visible, checksum-bound, and blocked until the database, source snapshot, process state, and backup destination all pass their preconditions.

Plan / apply separation
Planning is read-only and allowed while Rekordbox runs. Applying is a distinct command with a fresh safety gate.
Checksummed inputs
The plan records source snapshot and Rekordbox database checksums; drift produces a regenerate instruction, never an opaque partial apply.
Fail-closed button state
The primary action names the blocker instead of merely becoming an unexplained disabled button.
Transaction + backup
Apply creates a timestamped database backup before beginning the pyrekordbox transaction.
