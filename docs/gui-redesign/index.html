Sync planning — five design directions

Each page is a working mockup of the same screen: the interactive plan selector that today lives behind udl sync --plan. Same data model in all five (PlanRow with missing_new / missing_known_gap / already_downloaded, per-source target dir and state file, plan limit, plan window, dry-run). Selection, filters, sorting and options are live — click around. Every page has an ⓘ Swift mapping button listing the native components it assumes.

Option 1

Inspector

Three columns: sources, a sortable table, a persistent options inspector. Everything visible at once, Xcode/Finder shape.

Tune & re-scan fastDensest infoNeeds a wide window
Option 2

Focus

One list for the whole run with sticky per-source headers. Options hidden in a toolbar popover. Dark, Music.app-like.

Reads as one queueLeast chromeOptions one click away
Option 3

Review

A single centred document: headline counts as filters, collapsible source cards, plain-language summary before you commit.

Hardest to misreadGood for gapsMost scrolling
Option 4

Console

The TUI promoted to a GUI. Flat sortable table across all sources, full keyboard control, live copyable udl command bar.

Fastest for youKeyboard-firstUnfriendly to new users
Option 5

Guided

One source per page with a step bar, matching how --plan actually loops. Settings shown as editable value chips.
